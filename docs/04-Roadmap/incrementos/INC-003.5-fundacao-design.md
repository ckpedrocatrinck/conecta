### Decisões tomadas durante a implementação
- **Mapeamento `default` (verde) vs `action` (laranja) nas 4 telas**: só "Li e estou ciente" (aviso-privacidade) foi tratado como ação-core (equivalente a "declarar ciência" que o design-system usa como exemplo central). Login, trocar senha e salvar consentimentos ficaram verdes — são submissões de formulário de rotina, não a "ação que trava o núcleo do produto" que a regra de ouro reserva para o laranja. Isso não está escrito tela-a-tela no design-system.md; é uma leitura minha da intenção documentada. Sinalizado no plano antes de implementar.
- **Contraste do laranja**: calculei a razão de contraste de texto branco sobre `--action` (#D96E30) = **≈3,37:1** — não passa AA para texto normal (precisa 4,5:1), só para texto grande (≥18,66px negrito, WCAG). Por isso o novo tamanho `xl` do `Button` usa 20px negrito (contraste grande passa em 3:1). Não inventei um hex alternativo — mantive o laranja exatamente como documentado e ajustei o tamanho/peso do texto, que não estava especificado no design-system.
- **Dark mode**: implementei só os 4 valores de fundo/superfície/texto que o design-system dá em hex exato (seção 8). Não inventei o "ajuste de luminância para AA" do verde/laranja no escuro porque o documento menciona essa necessidade sem dar o hex resultante — decidir esse valor seria eu fazendo uma escolha de arquitetura visual não documentada. Registrado como pendência abaixo.
- **`Select` não foi reconstruído como componente**: o único uso (seletor de empresa no login) já usa as mesmas classes token-driven de `Input` (`border-input`, `ring-ring`) — herdou os novos tokens automaticamente. Construir uma primitiva `Select` completa do Base UI para esse único uso seria escopo maior que o necessário.
- **Tamanhos antigos de `Button`/`Input` preservados**: os tamanhos existentes (`default`, `sm`, `lg` antigo=36px, etc.) não foram alterados, para não afetar as telas de admin (fora do escopo deste INC). Só adicionei tamanhos novos (`xl` no Button, `lg` no Input) para as telas de colaborador.
- **`BottomNav` construído mas não integrado**: o design-system explicitamente delega a decisão dos 4–5 itens reais a um INC de navegação futuro. Construí o componente pronto visualmente, mas não o inseri em nenhuma tela para não inventar uma IA de navegação não documentada.
