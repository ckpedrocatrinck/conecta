# INC-008.5 — Navegação global (bottom nav + header admin)

**Status:** ⬜ Não iniciado
**Fase:** transversal (entre 3 e 4) — fundação de navegação, análoga ao INC-003.5 de design
**Depende de:** INC-008 (feed) mergeado; ADR-009 aceito
**ADRs relevantes:** 009 (navegação por papel), 002 (mobile-first), 003 (papéis)
**Resolve:** DP-10

## Por que este INC existe
Até aqui todas as telas são acessíveis só por link direto ou URL digitada à mão (o painel admin só aparece em `/admin`). Este INC implementa a navegação global do ADR-009 — bottom nav para colaborador, menu administrativo no header para admin — tornando o produto navegável sem decorar URLs. É fundação transversal: toca o layout, não uma feature isolada.

## Escopo

### 1. Bottom navigation (colaborador, e visível a todos os papéis)
- Popular o componente `BottomNav` (criado no INC-003.5) com os itens reais: **Início** (`/`), **Comunicados** (`/comunicados`), **Perfil** (`/perfil`).
- Item ativo destacado em `--primary` (design-system §4); inativo em `--muted-foreground`; ícones lucide.
- **Badge de pendência** no item Comunicados: contador de comunicados aguardando ciência do usuário logado — reusar `countPendingAcksForUser` (INC-005), NÃO recalcular. Some quando zero.
- Fixo no rodapé, alvos ≥48px, seguro em 360px e em safe-area de iOS (padding bottom).
- Aparece para employee, manager e admin (todos veem o produto de colaborador).

### 2. Header com menu administrativo (só admin)
- Header no topo, visível apenas quando `session.role === "admin"`, com acesso a: **Comunicados** (`/admin/comunicados`), **Posts** (`/admin/posts`), **Colaboradores** (`/admin/colaboradores`), **Filiais** (`/admin/filiais`), **Pendências** (`/pendencias`), **Auditoria** (`/admin/auditoria`).
- Em telas estreitas (360px) o menu admin colapsa de forma limpa (ex.: menu recolhível) — mas SEM reproduzir o hambúrguer-de-tudo da portal legado; é só o conjunto administrativo, organizado.
- Deixa de existir a necessidade de digitar `/admin` na mão.

### 3. Manager
- Bottom nav igual + um acesso a **Pendências** (`/pendencias`). Sem o menu admin completo. (Código dormente no piloto, mas correto por papel.)

### 4. Integração no layout
- A navegação é resolvida no layout raiz a partir do `role` da sessão — o que cada usuário vê depende do papel, aplicado no servidor (não esconder no cliente algo que o servidor serviria).
- Rotas administrativas continuam protegidas pelos guards existentes (`requireAdmin`/`requireAdminOrManager`) — a navegação é conveniência de UI, NÃO substitui a autorização de rota. Um employee que digite `/admin` continua bloqueado como antes.
- Remover/ajustar os links soltos "de emergência" que INCs anteriores puseram nas home (ex.: link "Painel de pendências" solto em `page.tsx`) agora que há navegação de verdade — sem quebrar nada.
- Adicionar o link **Posts** que faltava no painel admin (observado no QA do INC-008).

## Fora do escopo
- Vagas no bottom nav (entra no INC-011).
- Central de notificações dedicada (depende de mais decisão de produto; notificações in-app seguem na home).
- Redesenho de qualquer tela interna — só a navegação que as amarra.

## Critérios de aceite
- [ ] Colaborador vê bottom nav com Início/Comunicados/Perfil; item ativo destacado; tudo acessível sem digitar URL.
- [ ] Badge de pendência aparece no item Comunicados quando há pendência e some quando zera (bate com `countPendingAcksForUser`).
- [ ] Admin vê o bottom nav + menu administrativo no header com as 6 telas; nenhuma exige URL decorada.
- [ ] Employee que force `/admin/*` por URL continua bloqueado (navegação não afrouxa autorização).
- [ ] Manager vê bottom nav + acesso a Pendências, sem o menu admin completo.
- [ ] Tudo usável em 360px, sem scroll horizontal, alvos ≥48px, respeitando safe-area.
- [ ] Navegação resolvida por papel no servidor.
